- WHICH GENOMARK CONSTANTS ARE ACTUALLY DE-RISKED. The winning candidate's spec body was truncated in my inputs after the first sentence of its embed algorithm, so everything below its stated principle was reconstructed. Audiowmark-anchored (a shipped C++ implementation exists to diff against): N=1024, hop=512, frames_per_bit=2, band bins 20..100, Odenwalder K=9 rate-1/3 generators 557/663/711 octal, sync on every 4th chip. SET BY ME AND NOT DE-RISKED: DELTA, the dither construction, the 32-slot preamble and its PN, the pilot pattern, the guard mask and its frequency list, trim depth, the 24x12 interleaver, the rho grid, tau_sync, the 56-bit payload layout, CRC-32C. Do not let the second list inherit the first's credibility in any doc or commit message.
- CONFIRM THE ODENWALDER GENERATORS BEFORE WRITING THE VITERBI. 557/663/711 octal for K=9 rate-1/3 are quoted second-hand from a judge critique, not read from a primary source. Verify against Odenwalder's tables or a CCSDS/3GPP reference. This is cheap and it is load-bearing: wrong generators produce a decoder that works against its own encoder and fails against nothing else, which no round-trip test can catch.
- SIGMA_D IS THE NUMBER THE WHOLE RATE BUDGET HANGS ON, AND IT IS UNMEASURED. Build unit C0 exists to measure it before the embedder is written. If it lands above ~0.3 nepers, take the pre-specified frames_per_bit ladder (2->3->4) rather than redesigning. Track whether it varies enough BY CONTENT CLASS to justify a per-track DELTA instead of one global constant.
- THE GUARD MASK IS A HYPOTHESIS ABOUT REAL MASTERING CHAINS. GUARD_HZ = {1000,1200,2000,2500,3000,3500} costs 6 of 20 pairs, a 30% reduction in the statistic, to buy multiband-compression robustness. Bench row 11 (crossovers deliberately placed OFF the mask) is what decides whether it pays for itself. If it does not, the fallback is the C0-authorized band extension to bins 20..115 (24 pairs, 18 active) — but note that extension is mine, not audiowmark-anchored, and pushes the ceiling to 4953 Hz, closer to the 48 kbps HE-AAC crossover.
- HE-AAC v2 AT 32 KBPS IS THE ROW MOST LIKELY TO SURPRISE. I predict ~70% (SBR crossover falls at or above the band top so the mark survives the cut; Parametric Stereo collapsing the mid channel is the real damage). The rejected design predicted total destruction for its own band. I could be wrong in either direction and the prediction is recorded so the bench can refute it.
- THE POC'S signed_content_hash CANONICALIZATION IS UNDECLARED, WHICH IS A LATENT INTEROP BUG IN THE PRIOR ART. portable_signature carries an explicit canonicalization field ('apw-json-sort-v1'); manifest_signature carries none, yet uses a different canonicalization (the implicit ensure_ascii=True form at generator.py:425 and verify.py:392). Any future non-Python verifier will guess wrong on non-ASCII manifests. Worth reporting upstream; the TS side handles it, but only because it was found by reading the code rather than the field.
- ORDERING CONSTRAINT DISCOVERED WHILE READING, NOT YET REFLECTED ANYWHERE. verify.py:392 recomputes signed_content_hash over the manifest MINUS manifest_signature but INCLUDING portable_signature. So the portable signature must be applied before the manifest signature, permanently (generator.py:429's comment confirms the entanglement is deliberate). The TS signer must enforce this order explicitly rather than inheriting it by accident from statement order.
- IS THE FINGERPRINT RUNG WORTH BUILDING AT ALL FOR v1? It is default-off, can never produce `verified`, and carries a 64 MiB index plus a whole scoring subsystem. It may be better deferred to v1.1 and the effort spent on bench row 11 and the transparency campaign. I kept it because GenoTrace's ladder arbitration is cleaner to specify with all five rungs present, but that is a design-coherence argument, not a user-value one.
- THE PUBLIC NAMESPACE KEY IS A PRODUCT DECISION, NOT A TECHNICAL ONE. Namespace 0 uses a published constant, making the mark removable by anyone who reads the spec. That is correct for provenance recovery and wrong for tamper evidence. Whether the default registry should be a keyed namespace instead is David's call; the payload's 4-bit namespace field makes it reversible either way.
- WHETHER TO SHIP THE @audio-provenance/sdk ALIAS PACKAGE AT ALL. It makes the brief's snippet compile locally but publishing it to npm under an unregistered third-party scope is exactly what SCOPE.md warns against. My assumption is that it stays a workspace-only alias marked private:true and is never published. Reverse by deleting the alias package.
