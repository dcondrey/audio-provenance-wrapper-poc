# Manifest Schema

## Purpose

Define the v0.9 JSON fight-card manifest produced for one routed stem and one
detected WAV/AIFF export.

The JSON manifest is the primary evidence record. The adjacent HTML fight card
is a presentation derived from this JSON and adds no claims.

## Honesty model

Evidence claims use exactly one proof level:

- `directly_observed`
- `inferred`
- `user_declared`
- `externally_verified`
- `unknown_unobserved`

Schema and presentation metadata are not provenance claims. Claim-bearing
objects include `apw:proof_level`, or a specifically named proof field when one
object contains facts with different origins.

## Top-level structure

```text
apw_version
schema
session_id
capture_session
created_at
core_principle
observed_stems[]
export
ingredients[]                 (optional)
edit_history[]                (optional)
session_facts                 (optional, inferred from saved .als)
stem_export_association
claim_summary[]
apw:unobserved[]
evidence_binding
manifest_signature
presentation
c2pa_mapping
```

## Capture session

`capture_session.id` is generated by the local daemon when it starts. Its scope
is `local_daemon_runtime`; it is not asserted to be an Ableton project ID.

## Observed stem

The v0.9 demo uses one configured `stem_id`. Each stem contains:

- `hash_chain_root`: the final received window hash and commitment to the
  preceding complete emitted chain;
- `hash_chain_genesis`: normally `genesis` for the first window;
- `hash_chain_length`: number of received `buffer_hash` events;
- `first_observed_ms` and `last_observed_ms`: plug-in monotonic timestamps;
- `first_received_at` and `last_received_at`: daemon UTC receipt timestamps;
- sample rate and channel count reported by the plug-in;
- `source_category` and its separate `source_category_proof_level`;
- `apw:proof_level: directly_observed` for the routed-audio observation.

A non-unknown source category supplied on the command line is
`user_declared`. The default `unknown` category is `unknown_unobserved`.

## Export

The export object records filesystem-observed facts:

- resolved path and filename;
- SHA-256;
- WAV/AIFF format;
- file size;
- duration, sample rate, and channels when readable;
- UTC detection/export timestamp;
- `apw:proof_level: directly_observed`.

## Stem-to-export association

The daemon associates observations and an export because both occurred during
the same local capture session. This relationship is always labelled
`inferred`; it does not prove complete Ableton routing or exclude bypassed
audio.

## Claim summary

`claim_summary` is a human-readable fight card covering:

- routed audio observed;
- export file hashed;
- observed stem associated with export;
- source category;
- full Ableton provenance explicitly not claimed.

Each summary entry has `claim`, `value`, `evidence`, and `apw:proof_level`.

## Evidence binding

JSONL evidence files continue to receive events after an export. Therefore the
manifest binds the immutable file prefix present when the manifest was created:

- evidence filename;
- SHA-256 of the prefix;
- prefix byte length;
- binding scope `file_prefix_at_manifest_creation`.

The verifier hashes exactly that prefix, so later appended events do not
invalidate an earlier manifest.

## Integrity seal

The current operational signer is a filesystem-stored HMAC-SHA256 key.
`manifest_signature` records:

- algorithm and local signer ID;
- signature and signed-content hash;
- `trust_scope: local_software_integrity`;
- `hardware_attested: false`;
- `apw:proof_level: unknown_unobserved` for hardware/device attestation.

This can detect manifest changes when checked in the same local key context. It
does not provide a public-key identity, Secure Enclave attestation, or external
verification.

## C2PA alignment

`c2pa_mapping` is explicitly marked
`mapping_only_not_an_embedded_c2pa_manifest`. It demonstrates how selected
hash, ingredient, action, and unobserved records may map to C2PA concepts.

It is not a conforming embedded C2PA manifest or production C2PA signature.

## Unknown and unobserved facts

`apw:unobserved` always identifies material gaps, including hidden plug-in
state, internal preset logic, bypassed routing, DAW-internal processing, and
unverifiable upstream provenance. Inactive observation layers are added to this
list for each capture session.
